Great question — and the answer is important because this changes how you use Android Studio entirely. **You don't rebuild the app in Android Studio for React Native code changes.** Your project already has `expo-dev-client` installed and an `android/` directory, so you get **Fast Refresh**: edit TS/TSX → the app updates instantly on device/emulator.

Here's the optimal workflow for DukkanPro:

## 🏆 Optimal Daily Workflow (JS/TS changes only)

**Terminal 1 — start the Metro dev server:**
```bash
cd /home/faroub/Documents/Projects/DukkanPro
npx expo start --dev-client
```

**Device/Emulator:**
1. Start your Android emulator (or plug in a device with USB debugging + `adb devices` shows it)
2. Launch the **DukkanPro** app from the home screen — the dev-client launcher auto-detects and connects to the Metro server

**Now just edit code.** Every change to `.tsx`/`.ts` files under `src/` hot-reloads instantly (Fast Refresh). No Gradle, no Android Studio run button, no waiting.

Useful shortcuts in the Metro terminal:
- `r` — manual reload
- `m` — open dev menu
- `j` — open debugger (Chrome DevTools / React Native DevTools)

## 🔨 When You Actually Need to Rebuild (native changes only)

Rebuild is needed **only** when you:
- Install/update a library with native code (e.g. new `expo-*` package)
- Change `app.json` / app config
- Upgrade the Expo SDK

Then run:
```bash
npx expo prebuild --clean   # regenerate android/ from config
npx expo run:android        # build + install + start server
# add --device to install on a physical phone
```

## 🤖 What Android Studio Is Actually For

Keep it open only for:
- **Logcat** — viewing native crash logs (`adb logcat` works too)
- Inspecting generated native code in `android/`
- Building a **release APK/AAB** for distribution (`Build > Generate Signed Bundle`)

⚠️ Don't use the Android Studio ▶️ Run button for daily development — it embeds the JS bundle at build time (see your `build.gradle`'s `bundleCommand = "export:embed"`), making every change a slow Gradle rebuild. Always load JS from Metro via the dev client instead.

## 📋 Summary Cheat-Sheet

| Task | Command |
|---|---|
| Daily development | `npx expo start --dev-client` |
| First build / after native changes | `npx expo run:android` |
| Physical device | `npx expo run:android --device` |
| Regenerate native dirs after config change | `npx expo prebuild --clean` |
| Web dev (also in your scripts) | `npm run dev` (port 3000) |
| Unit tests | `npm test` |
